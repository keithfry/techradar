ROS Discourse General: Should robot software have execution authorization separate from deployment?

A system called RLSOK was developed to separate software deployment from execution authorization for robots. It addresses the issue that deployed software might not still be authorized to cause physical actions if conditions change. RLSOK checks release identity, approval status, configuration binding, and execution permits before dispatching robot commands. This layer does not replace existing safety systems like E-stops or motion planning. The author seeks feedback from real-world ROS 2 robot operators regarding existing execution authority mechanisms.
